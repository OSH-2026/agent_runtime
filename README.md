# OSH-26 Agent Runtime

本仓库为中国科学技术大学 OSH-2026 课程大作业项目仓库，聚焦于 LLM Agent 的执行层工程化实现。项目以 Action Fabric 为核心叙事，目标是在端侧场景下提供可验证、可扩展、可恢复的结构化执行能力。

## 项目介绍

传统 Agent Loop 执行范式具有依赖关系不可验证、执行路径不可分析、错误恢复不可控等问题。Action Fabric 将执行过程显式化为 DAG（有向无环图），以调度器驱动就绪集合（ready set）计算与节点执行，形成确定性的执行内核，并通过分层恢复策略实现有界重试与可控恢复。

项目当前主要包含两类工程实体：

- `dispatcher`：Rust 编写的调度内核，包含执行计划、状态机、就绪集合计算、调度策略、执行引擎与恢复层等核心模块。
- `actions`：Rust ↔ Kotlin 的执行桥，统一 Action 抽象，提供远程执行（RPC/IPC）能力，支持异步 Action 的调度与结果回传。

## 目录结构

```
agent_runtime/

```

## 落地现状

- 完成 `dispatcher` 与 `actions` 的工程骨架搭建，核心模块与类型已按论文模型落地。
- 调度内核具备 DAG 校验、节点状态机、就绪集合计算与 side-effect 并发约束。
- 执行引擎完成可运行闭环：执行、审计日志、状态持久化、诊断上下文采集。
- Recovery 层具备可配置重试预算与升级门控，并与诊断上下文解耦。
- Rust ↔ Kotlin 侧执行桥具备 gRPC 协议草案与远程 Action 调用接口骨架。
- 已实现 ActionFlow 静态文件 loader，按数据引用自动建图并生成执行计划。
- 示例 `dispatcher_demo` 可在本地运行，验证 DAG 调度与 Action 执行流程。

## 下一步计划

- 补齐 ActionFlow loader 的序列化规范文档与字段约束，提供更多样例。
- 实现 Join 语义（all-of / any-of）与条件分支的模型化支持。
- 接入真实 gRPC 实现，完成 Kotlin 服务端最小可运行版本。
- 为审计日志与状态存储提供可选的文件持久化后端。
- 增加端到端测试与回放验证，覆盖失败与恢复路径。
